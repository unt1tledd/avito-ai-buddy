# База знаний AI-buddy: демоматериалы, чек-лист и учебная практика

Версия **1.3**, обновлена 13.11.2026. В корпусе **304 исходных документа**, 10 разделов, 47 подразделов и **589 проверочных сценариев**. После штатного разбиения получается **352 чанка**. Объём исходных текстов — 261 277 символов, примерно в 3,3 раза больше версии 1.2.

Происхождение материалов:

- **85 прежних демостатей** — вымышленные процессы, сроки, адреса, льготы и контакты, помеченные `[ДЕМО]`.
- **59 фрагментов по предоставленному Excel**: 47 уникальных пунктов, 11 сводок по периодам и памятка. Исходные формулировки, ссылки на листы/строки и периоды сохранены. Актуальность файла как действующей политики компании отдельно не подтверждена.
- **160 новых авторских учебных материалов**, также `[ДЕМО]`: 96 инструкций для стажёра и наставника и 64 статьи только для наставника. Это рекомендации для учебного сценария AI-buddy, **не утверждённые правила Авито**. Они не добавляют отсутствующие факты в Excel, не создают настоящие URL, SLA, персональные назначения или выданные права.

Все 144 исходные записи версии 1.2 сохранены без изменений, включая ID, текст, URL, ACL, keywords и политику proposal. Их контрольные суммы находятся в `sources/baseline-v1.2-hashes.json`.

Редактируйте новые материалы в `sources/learning-expansion-v1.3.json`, затем из каталога `ai` выполните:

```sh
uv run --locked python knowledge/build_learning_corpus.py
uv run --locked pytest tests/test_knowledge_corpus.py tests/test_chunking.py -q
```

Сборка не вызывает внешние API и не изменяет БД. Она проверяет контрольные суммы исходных документов, Pydantic-схему, лимиты и ссылки эталонов. Повторный запуск не дублирует статьи и сценарии. Не редактируйте производные `learn-*` записи только в `documents.json`: следующая сборка восстановит их из источника. Для намеренного изменения исходного корпуса требуется отдельный пересмотр контрольных сумм.

## Права и источники

Стажёру доступны **232 документа**, наставнику — **304**. Только `mentor` доступны **72**: восемь прежних закрытых записей и 64 новых руководства наставника. Общая учебная статья не пересказывает закрытую оценку или личную переписку. Право определяет сервер по роли из доверенного `actor`, а не по тексту вопроса «я наставник».

Во всех текущих документах `teams=[]`: ограничений по команде нет. ID `101` в сценариях — тестовое значение, а не настоящая команда. Направление Backend из Excel не является ID команды.

Новые учебные статьи и Excel-фрагменты имеют `url=null`: реальные страницы по ним не создавались. Происхождение новых текстов прослеживается по ID в авторском каталоге. Прежние `.example` ссылки и вымышленные контакты сохранены только в исходных демостатьях. Настоящих секретов, личных зарплат и приватных оценок в корпусе нет.

`knowledge.md`, исходники и eval содержат закрытые статьи и эталоны. Не передавайте полный файл стажёру или в модель в обход ACL. Для RAG импортируется только `documents.json` с сохранением ролей. LLM-контекст создаётся штатным импортером и не становится источником фактов или цитат.

## Различие с исходным Excel

Чек-лист «Чек-лист  стажера.xlsx» содержит листы «Материалы для всех» и «Чек-лист Backend». В исходнике 48 строк задач, но опрос повторён в строках 16 и 17 общего листа: в корпусе сохранено 47 уникальных пунктов. Исходные ячейки и карта происхождения не изменены.

Сохранены периоды: первая и вторая недели, первый, второй и третий месяцы, после трёх месяцев. Экватор Excel — **после 3-х месяцев**. Шестая неделя в прежней демостатье — отдельный вымышленный сценарий. Семь слайдов из демофинала не являются числом слайдов экватора Excel. Настоящие URL курсов, точные команды avito-cli и персональные календарные даты в исходном файле отсутствуют и не добавлены учебным расширением.

Учебная статья, прочитанный материал или ответ AI не доказывают выполнение шага конкретным пользователем. Новые записи не создают пользователей, задачи, роли, ресурсы и шаги onboarding. Назначение и состояние плана поступают из соответствующей авторитетной системы.

## Импорт

**Расширение подготовлено в файлах; в рабочую БД этой операцией не импортировано.** При импорте штатный CLI вызывает настроенные внешние LLM/embeddings и атомарно заменяет весь корпус. Нужны допустимость передачи данных, согласованные настройки профиля у импортера/сервера и резервная копия существующей БД.

Сохраняются пределы: до 1000 исходных документов, 4 МиБ JSON, 4000 символов на документ и 4000 чанков. Чанки — до 1200 символов. Между законченными абзацами перекрытия нет; внутри длинного абзаца повторяются только целые предложения суммарно до 150 символов. Если целое предложение не помещается в перекрытие или требуется разрыв по слову/символу, перекрытие не добавляется; оригинальный текст и generated_context хранятся отдельно. Текущий JSON занимает около 607 КиБ и укладывается в ограничения.

1. Примените все миграции AI, включая `000004_hybrid_search.sql`, к подготовленной PostgreSQL с pgvector. Не применяйте первую миграцию вслепую поверх вручную созданных таблиц.
2. Настройте `KNOWLEDGE_DB_DSN`, LLM и embeddings, подтвердите обработку через `KNOWLEDGE_PROCESSING_APPROVED=true`. Для OpenRouter требуется фиксированный `EMBEDDING_PROVIDER`.
3. Из каталога `ai` выполните полный импорт:

```sh
IMPORT_TIMEOUT_SECONDS=1800 CONTEXT_CONCURRENCY=1 CONTEXT_MIN_INTERVAL_SECONDS=3 \
  uv run --locked --env-file ../.env python -m ai_service.rag.import_documents knowledge/documents.json
```

Настройки контекстуализации и профиля должны совпадать у импортера и сервера. Интервал 3 секунды — пример ограничения частоты для провайдера; он не устанавливает SLA. При холодном кеше для 352 чанков один только интервал запуска требует более 17 минут, поэтому в примере `IMPORT_TIMEOUT_SECONDS=1800` вместо стандартных 900 секунд. Подготовленные контексты переиспользуются из кеша.

После успешного импорта ожидаются **352 строки `documents` и `document_chunks`**: существующий репозиторий сохраняет отдельную запись документа на каждый чанк. В `document_access` ожидаются **608 строк**: 256 общих чанков × 2 роли и 96 закрытых × 1 роль. Проверьте `/readyz`, разрешённый вопрос и запрет выдачи наставнической статьи стажёру. Не импортируйте только дополнение: импортер заменяет весь корпус.

Полное описание профилей, кеша, атомарности и переиндексации: [hybrid-search.md](../specs/hybrid-search.md).

## Проверка и примеры

Примеры вопросов стажёра: «Как отличить ожидание пула от медленного SQL?», «Что делать с несовместимыми замечаниями ревью?», «Почему увеличение серверного дедлайна не продлевает ожидание клиента?», «Как проверить источник ответа AI?»

Примеры вопросов наставника: «Как учитывать степень помощи в оценке?», «Что делать, если данных для оценки навыка нет?», «Как принять исследование без улучшения метрики?», «Как передать сопровождение резервному наставнику?»

В eval сохранены все 305 прежних сценариев и добавлены 284: 160 вопросов по новым статьям, 48 по подробным примерам, 64 ACL-проверки и 12 вопросов об отсутствующих сведениях. Для длинных статей ожидаемые `source_id` вычислены штатным chunking; название исходного документа не подставляется вместо ID части. Эталоны проверяют рекомендации, а не вымышленные персональные результаты.

Исторический [отчёт гибридного поиска](../specs/hybrid-search-results.md) относится к версии 1.2 (144 документа), не к расширенному корпусу. Новый внешний прогон ещё не выполнен. Для повторного сравнения используйте новый путь отчёта:

```sh
AI_TEST_POSTGRES_DSN='postgresql://.../disposable_test_db' \
  uv run --locked --env-file ../.env python tests/eval_hybrid_search.py --live \
  --output evals/hybrid-search-v1.3.json
```

## Политика proposal

Новые учебные статьи **не добавляют `access_policies`**. Сохранена только прежняя демонстрационная политика `synth-repository-access`: host `git.avito.example`, уровень `Developer`. Это метаданные вымышленного примера, не выданное право. Сведения о предложении доступа нельзя выводить из общего текста о безопасности, наставничестве или технических ролях.
