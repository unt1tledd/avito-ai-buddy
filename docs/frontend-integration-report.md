# AI-buddy: отчёт о подключении интерфейса и исправлении интеграции

Дата: 13 ноября 2026 года. Рабочая ветка: `frontend-integration`.

## Цель

Превратить демонстрационный React-интерфейс в приложение, которое работает
с настоящими пользователями, планами адаптации, сообщениями и заявками.
Первоначально менялись фронтенд и Nginx; позднее пользователь разрешил изменения
сервисов Chat и AI для независимых чатов и исправления ответов.

## Почему раньше приложение выглядело рабочим, но не было подключено

- Клиент обращался к `/api/v1/...`, тогда как публичные маршруты сервера начинаются с `/v1/...`.
- При ошибке запроса клиент подставлял готовые ответы и фиктивное успешное подтверждение заявки.
- Чек-лист и история содержали демонстрационные данные.
- Галочки обновлялись в памяти страницы без сохранения на сервере.
- Загруженный прогресс принудительно сбрасывался в `completed: false`.
- Получение предложения заявки ошибочно трактовалось как выданный доступ.
- Конфигурация Nginx существовала, но не подключалась к контейнеру frontend.

## Что изменено

### Фронтенд и Nginx

- Конфигурация `infra/nginx/nginx.conf` подключена к контейнеру через Docker Compose.
- Сайт доступен на `http://localhost:8085`; Vite на 5173 проксирует API и WebSocket через 8085.
- Клиент приведён к действующим адресам и структурам JSON: Chat использует camelCase, Onboarding — snake_case.
- Удалены локальные ответы по ключевым словам, фиктивные номера заявок и подмена ошибок успехом.
- Подключены вход, регистрация и обновление сессии. Bearer-токен хранится в памяти; HttpOnly cookie используется браузером для WebSocket.
- Добавлена форма профиля стажировки для аккаунтов, зарегистрированных в Auth, но ещё не имеющих данных в User.
- Даты обязательны для User API. Форма явно предлагает тестовый период на шесть месяцев с текущей даты; ручной ввод остаётся доступен.
- Подключены история с пагинацией, отправка вопросов и повтор с исходным текстом и тем же числовым ключом идемпотентности.
- Подключены загрузка плана, назначение отсутствующего плана и сохранение/снятие галочек.
- Во время сохранения блокируется выбранная галочка. Отметка пользователя не зависит от статуса заявки.
- Подтверждение заявки показывает статус сервера, а не автоматически «доступ выдан».
- Добавлены WebSocket, переподключение и обновление данных после событий.
- Восстановлены прежние логотип, переключатель темы, иконки истории/Roadmap и оформление чата.
- Убраны приветственная надпись, технические элементы основной области и кнопка «Отправить».
- Enter отправляет вопрос, Shift + Enter добавляет новую строку.

### Независимые чаты

Раньше сервер хранил одну беседу на пользователя. Поэтому пункты истории открывали
одну и ту же переписку, а очистка экрана не сбрасывала контекст ИИ.

Теперь:

- Добавлена миграция `chat/migrations/migrations/000007_multiple_conversations.sql`.
- Пользователь может иметь несколько бесед; прежняя беседа сохраняется совместимой с устаревшими вызовами.
- Добавлены HTTP-операции:
  - `GET /v1/chat/conversations` — список чатов владельца;
  - `POST /v1/chat/conversations` — создание;
  - `DELETE /v1/chat/conversations/{id}` — удаление выбранного;
  - `DELETE /v1/chat/conversations` — очистка чатов владельца.
- Заголовок `X-Conversation-Id` выбирает беседу для отправки вопроса и чтения истории.
- Сервер проверяет владельца выбранной беседы.
- «Новый вопрос» открывает пустую область; первый вопрос создаёт отдельную серверную беседу.
- Название чата берётся из первого пользовательского сообщения.
- История, передаваемая ИИ, ограничена выбранной беседой.
- Добавлены переключение между чатами и удаление через интерфейс.
- Удаление мягкое: беседа недоступна через API, но строки остаются в базе для связанных заявок и аудита.
- Подтверждение предложения из удалённой беседы закрыто.
- Старая беседа текущего аккаунта очищена через интерфейс. Другие пользовательские аккаунты массово не удалялись.

### Почему ИИ начал отвечать

Обнаружены и устранены несколько разных проблем:

1. **Отсутствовал профиль стажировки.** Chat завершал обработку с `internship not found` ещё до вызова AI. Добавлено заполнение профиля через существующий User API.
2. **Были отключены шаблоны плана.** При `ONBOARDING_SEED_DEMO=false` сервер не мог назначить Backend-план. Для локального окружения включены предусмотренные проектом шаблоны.
3. **AI-контейнер был устаревшим.** Он падал из-за старого ограничения таймаута. Контейнер пересобран из текущих исходников.
4. **База знаний была не подготовлена.** Поиск возвращал `schema_missing`. Применены предусмотренные проектом миграции AI до версии 3.
5. **В базе было 0 документов и 0 фрагментов.** После разрешения пользователя импортирован подготовленный командой демо-корпус через настроенный embeddings-провайдер.
6. **Модель иногда пропускала поиск.** Добавлена одна корректирующая попытка: сервис просит модель выполнить поиск перед фактическим ответом. Проверки источников и прав не отключены.

Одинаковая фраза «Что именно вы хотите уточнить?» — контролируемый шаблон
уточнения AI-сервиса. Это не проверка ключевых слов в React. Такой ответ может
оставаться уместным для непонятного запроса; успешная интеграция не гарантирует
содержательный ответ на произвольную бессмыслицу.

Корпус содержит демонстрационные материалы: его ответы нельзя выдавать за
проверенные действующие регламенты Авито.

## Проверки

В ходе работы выполнены:

- сборка фронтенда TypeScript/Vite;
- 9 тестов API-клиента;
- 352 AI-теста из `test_chat.py`, включая восстановление после пропущенного поиска;
- Go-тест авторизации HTTP-операций с чатами;
- интеграционная проверка через настоящий Nginx/API: регистрация, вход, профиль, план, установка и снятие галочки с повторным чтением;
- реальные вопросы об отгуле и персональных данных: ответы получены с одним и двумя источниками соответственно;
- проверка независимой истории двух чатов, запрета чтения чужой беседы, удаления и очистки списка;
- визуальная проверка пустого чата и удаления старой беседы через браузер;
- `git diff --check`.

Часть старых Go-тестов репозиториев/usecase не запустилась из-за отсутствующих
сгенерированных mocks. Полное покрытие проекта и выполнение требования хакатона
о покрытии более 80% этим отчётом не подтверждаются.

## Что ещё важно

- Последняя поправка маршрутизации асинхронных уведомлений в беседу исходной заявки находится в коде. Её применение к контейнеру было отклонено пользователем; повторно без разрешения команда не запускалась.
- Эта последняя поправка не проходила отдельную интеграционную проверку после изменения. Предыдущие успешные проверки относятся к версии до неё.
- Чтобы применить её, из корня проекта выполнить:

```sh
docker compose up -d --build --no-deps chat
```

- Интерфейс согласующего не подключён; внутренний Task API не опубликован в браузер.
- Автоматическое завершение шага по решению заявки и отдельное предложение завершить шаг из чата не заявляются как полностью проверенные сценарии.
- Секреты не включаются в Git. Локальная настройка шаблонов в `.env` не заменяет настройку окружений других участников.
- Текущие изменения в `frontend-integration` не были автоматически закоммичены или отправлены в MR.

## Как воспроизвести проверки

```sh
npm test --prefix frontend
npm run build --prefix frontend
go test ./chat/internal/app
python3 frontend/tests/integration_chat.py
```

Последняя команда требует работающего локального стека, создаёт отдельные
тестовые аккаунты и вызывает реальную модель, поэтому расходует её API-квоту.
