# AI Buddy: продукт и границы MVP

Статус: начальное описание по реализации на 16.11.2026. Это база для согласования, а не подтверждение готовности развёрнутого продукта. Известные дефекты, противоречия и решения, которых нет в коде, перечислены в [spec-review.md](spec-review.md).

## Цель

Помочь стажёру освоиться в команде: найти инструкции и учебные материалы, видеть назначенные шаги адаптации, вести переписку с помощником и подтверждать подготовленные заявки на доступ. Формулировка следует из [главной страницы](../frontend/src/pages/HomePage.tsx), [Roadmap](../frontend/src/pages/OnboardingPage.tsx) и [чата](../frontend/src/pages/ChatPage.tsx). Количественные продуктовые цели в исследованных источниках не заданы.

## Аудитория и участники

| Участник | Подтверждённая роль |
|---|---|
| Стажёр | Основной пользователь подключённого интерфейса: аккаунт, профиль, Roadmap, чат и заявки. |
| Наставник и руководитель | Данные наставника и членства в команде существуют в User. В корпусе есть материалы для `mentor`, но отдельный подключённый кабинет наставника и получение этой роли через Chat не подтверждены. |
| Внешний tracker | Доверенный клиент API Task: читает ожидающие заявки команды и передаёт решение с реквизитами решающего лица. Интерфейс или конкретная внешняя система tracker в репозитории не реализованы. |
| Оператор знаний | Использует существующий CLI импорта корпуса; это технический процесс, отдельный от интерфейса стажёра. |

Основания: [App](../frontend/src/App.tsx), [User API](../user/api/user/v1/user.proto), [роль для AI](../chat/internal/adapter/user/grpc/client.go), [Task API](../task/api/task/v1/task.proto), [CLI импорта](../ai/src/ai_service/rag/import_documents.py), [описание корпуса](../ai/knowledge/README.md).

## Основные сценарии

1. **Начать работу.** Зарегистрироваться по email и паролю, войти, заполнить профиль стажировки, если метаданных ещё нет. Аккаунт Auth и профиль User создаются отдельными операциями. Основания: [App](../frontend/src/App.tsx), [SetupPage](../frontend/src/pages/SetupPage.tsx).
2. **Посмотреть адаптацию.** Открыть существующий план, выбрать трек и шаг, увидеть описание, период и прогресс. Завершить или повторно открыть шаг, затем перечитать серверное состояние. Назначение плана другим человеком пока не образует подтверждённый пользовательский путь. Основания: [Roadmap](../frontend/src/pages/OnboardingPage.tsx), [PlanService](../onboarding/internal/usecase/plan/plan.go).
3. **Найти ответ.** Создать или выбрать чат, отправить вопрос, получить сохранённый ответ и использованные источники. При ошибке повторить отправку с прежним ключом. Вопрос о шаге можно подготовить из Roadmap; пользователь отправляет его сам. Основания: [ChatPage](../frontend/src/pages/ChatPage.tsx), [MessageService](../chat/internal/usecase/message/message.go).
4. **Запросить доступ.** Получить допустимый черновик от AI, проверить ресурс и уровень, явно подтвердить отправку. Backend доставляет команду через Kafka в Task. Заявка создаётся один раз на предложение. Основания: [проверка черновика](../ai/src/ai_service/rag/proposals.py), [подтверждение](../chat/internal/usecase/action/action.go), [интеграционные тесты](../integration-tests/task_test.go).
5. **Получить решение.** Tracker одобряет или отклоняет заявку; событие сохраняет решение в исходной переписке. WebSocket ускоряет обновление, а история остаётся доступной после отключения. Список собственных заявок существует в API Task; текущий frontend имеет дефект преобразования его ответа, см. D1 в review. Основания: [Task repository](../task/internal/repository/task/postgres.go), [TaskStatus](../chat/internal/usecase/taskstatus/taskstatus.go), [frontend API](../frontend/src/lib/api.ts).

## Границы MVP по текущей реализации

| Область | Подтверждённый объём | Ограничение |
|---|---|---|
| Доступ | Email/пароль, JWT, refresh с ротацией, выход из текущей refresh-сессии | Восстановление пароля, SSO и выход со всех устройств не подтверждены текущим API. |
| Профиль | Создание и чтение профиля, команды, наставника и сроков | Редактирование профиля и управление справочниками из UI отсутствуют. |
| Адаптация | API назначения, чтение плана/контекста, завершение и переоткрытие | Инициатор назначения не согласован; штатные шаблоны содержат `common` и `backend`. |
| Чат | Несколько диалогов, история, удаление, идемпотентная отправка, источники | Удаление реализовано как скрытие записей; политика физического удаления не задана. |
| Знания | RAG с ACL, цитатами, ограниченным контекстом и резервными путями | Учебный и демонстрационный корпус не является утверждённой политикой компании. |
| Заявки | Черновик, подтверждение, реестр Task, события создания/ошибки, решения и повтор отправки | Выдача прав в целевой системе не реализована; ограничения проверки исправления D2 указаны в review. |

Основания: [Auth routes](../auth/controller/api.go), [User contract](../user/api/user/v1/user.proto), [шаблоны](../onboarding/migrations/demo.sql), [Conversation SQL](../chat/internal/repository/conversation/queries.sql), [AI contract](../ai/api/ai/v1/openapi.yaml), [Task contract](../task/api/task/v1/task.proto), [границы знаний](../ai/knowledge/README.md).

Прочтение статьи, ответ AI, подтверждение заявки и её одобрение не являются автоматическим завершением шага. Завершение хранит Onboarding, заявку — Task, переписку и предложения — Chat. Общего трекера рабочих задач в подтверждённом объёме нет: название сервиса Task относится к заявкам на доступ. Основания: [StepService](../onboarding/internal/usecase/step/step.go), [TaskService](../task/internal/usecase/task/task.go), [тест разделения действий](../frontend/tests/onboarding.test.mjs).

## Карта спецификаций

- [auth](../openspec/specs/auth/spec.md) — аккаунты и сессии.
- [user-profile](../openspec/specs/user-profile/spec.md) — профиль стажировки и владение данными.
- [onboarding](../openspec/specs/onboarding/spec.md) — планы, текущие шаги и прогресс.
- [chat](../openspec/specs/chat/spec.md) — диалоги, сообщения, история и контекст AI.
- [ai-knowledge](../openspec/specs/ai-knowledge/spec.md) — ответы, поиск, ACL и импорт знаний.
- [access-requests](../openspec/specs/access-requests/spec.md) — подтверждённая отдельная область заявок; реализуется совместно AI, Chat и Task.

## Достоверность и проверка

Требования извлечены из кода, контрактов и тестовых ожиданий. При подготовке документов тесты приложения, инфраструктура и внешние API не запускались. Формат проверяется отдельно командой `openspec validate --all --strict`; её успех не доказывает выполнение требований кодом.

[Межсервисные тесты](../integration-tests/README.md) используют настоящий backend и заглушку AI, без браузерного интерфейса. [AI-тесты](../ai/tests/test_rag.py) включают сценарии с PostgreSQL и подставными моделями. [Документация корпуса](../ai/knowledge/README.md) отдельно оговаривает отсутствие полного внешнего прогона текущей версии. Метрики качества, SLA, бюджеты и критерии продуктового успеха этим описанием не устанавливаются.
