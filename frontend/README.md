# Интерфейс AI-buddy

React + TypeScript + Vite. Все запросы идут через единый адрес `/v1/...`.
В Docker Compose конфигурация `infra/nginx/nginx.conf` монтируется в контейнер
frontend: Nginx раздаёт сборку и направляет API-запросы в сервисы.
Внутренние Task API не публикуются в браузер.

## Запуск

Из корня проекта при запущенном Docker и подготовленном командой `.env`:

```sh
docker compose up -d --build
```

Открыть http://localhost:8085. Для входа нужна существующая учётная запись
Auth с подготовленными метаданными стажировки в User. Регистрация только в Auth
не создаёт профиль стажировки автоматически. Пароли и служебные токены во
фронтенд не вшиваются.

Для разработки интерфейса при работающем стеке на 8085:

```sh
cd frontend
npm ci
npm run dev
```

Открыть http://localhost:5173. Vite проксирует `/v1`, включая WebSocket, в Nginx
на 8085. При изменении серверной конфигурации перезапустить контейнер frontend.

## Проверки

```sh
npm test
npm run build
```

Клиентские тесты проверяют преобразование реальных контрактов, сохранение
статусов, повторную авторизацию, отсутствие фиктивного успеха, назначение плана
и снятие отметки. Они используют имитацию HTTP и не заменяют проверку всего стека.

В браузере проверить: вход; ответ со ссылками; историю после перезагрузки;
выполнение и повторное открытие шага с сохранением после перезагрузки;
отправку заявки со статусом сервера; обновление по WebSocket после решения,
которое команда выполняет через внутренний Task API; повтор вопроса после сбоя.
Новый вопрос получает новый числовой ключ, повтор — тот же ключ и текст.

## Особенности интеграции

- Chat отдаёт protobuf JSON в camelCase, Onboarding — в snake_case.
- Access token из login/refresh хранится в памяти для Bearer-запросов Onboarding.
  Серверная HttpOnly cookie используется браузером для WebSocket.
- История — единая беседа пользователя, с пагинацией; отдельные фиктивные диалоги удалены.
- План назначается через POST `/v1/users/{id}/plan`, только если GET вернул 404.
- При событиях и восстановлении WebSocket клиент перечитывает историю и план.
  Сам факт одобрения заявки не подменяет серверный статус шага.
- Автоматическое завершение шагов и предложение завершить шаг из чата зависят
  от реализации бэкенда. Фронтенд не выводит успешное выполнение из текста ИИ.
- Интерфейс согласующего не подключён: `/internal/...` остаётся закрытым в Nginx.
